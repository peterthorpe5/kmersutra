KmerSutra v0.39.0 release notes
=================================

Purpose
-------
This release is a package-level update for comparable benchmark reporting and
threshold diagnostics. It does not change the core k-mer screening algorithm or
rebuild any database. It is designed to help decide whether a more permissive
call-promotion setting is worth a full 532-sample rerun after the v0.34
Plasmodium/outgroup panel showed weaker LOD50/LOD100 values than the earlier
v0.30 benchmark.

Main additions
--------------
1. Adds an installed comparable benchmark summary command:

       kmersutra-summarise-comparable-benchmark

   This exposes the comparable summary workflow directly through the package.

2. Updates the existing kmersutra-summarise-run command to dispatch comparable
   benchmark arguments such as --out_root, --manifest and --out_dir to the
   comparable summary workflow, while preserving the old --summary_tsv / --out_xlsx
   / --out_html behaviour for legacy summary formatting.

3. Adds a new threshold-sweep diagnostic command:

       kmersutra-threshold-sweep

   This command reads an existing kmersutra_detection_calls_long.tsv or
   .tsv.gz table and reinterprets the same evidence under several candidate
   call-promotion thresholds. It does not rerun read screening.

4. Promotes the comparable summary implementation into the package as:

       kmersutra.comparable_benchmark_summary

   The top-level and summary-folder scripts are retained as compatibility
   wrappers around the package module.

5. The threshold-sweep command writes:

       threshold_sweep_target_performance.tsv
       threshold_sweep_real_world_summary.tsv
       threshold_sweep_by_family_spike.tsv
       threshold_sweep_off_target_summary.tsv
       threshold_sweep_neighbour_lineage_summary.tsv
       threshold_sweep_by_sample.tsv
       kmersutra_threshold_sweep.xlsx
       kmersutra_threshold_sweep.html
       kmersutra_threshold_sweep.log

Decision rule
-------------
A final full screen at u8_p1_e8 is only worth running if the threshold sweep
predicts a meaningful LOD/sensitivity improvement while keeping shuffled
negative samples clean, tracked-target specificity at or near 1.0, no broad
non-Plasmodium off-target expansion, and same-genus Plasmodium signals limited
to interpretable neighbour-lineage evidence.

Testing
-------

Repository hygiene
------------------
This is a package release. It intentionally avoids adding ad hoc rescue scripts.
Temporary analysis scripts should remain outside the GitHub-managed package
repository unless they become tested, documented package code.
